# 布道者贡献编辑抽屉设计

## 目标

解决管理员点击成员的“+贡献”或贡献记录的“编辑”后，需要滚动到页面顶部才能看到表单的问题。新增和编辑贡献都在当前视口内完成，且不改变现有数据接口与字段。

## 交互方案

- 移除页面顶部固定展示的贡献表单，仅保留成员管理区域。
- 点击“+贡献”时，从页面右侧打开抽屉，并初始化该成员的新贡献表单。
- 点击贡献记录的“编辑”时，在同一抽屉中载入原记录。
- 抽屉标题区显示“添加贡献”或“编辑贡献”，并展示当前成员姓名，避免误操作。
- 抽屉底部固定“取消”和“添加贡献/更新贡献”按钮；表单内容单独滚动。
- 点击关闭按钮、取消按钮或遮罩关闭抽屉。按 `Escape` 关闭抽屉，并在打开时阻止页面背景滚动。
- 保存成功后关闭抽屉，刷新当前成员的贡献记录及成员积分；保存失败时保留表单并显示现有错误提示。

## 响应式布局

- 桌面端抽屉固定在右侧，宽度不超过 560px，背景列表仍可作为上下文查看。
- 窄屏端抽屉占满视口宽度和高度，表单字段由双列变为单列。
- 遮罩和抽屉层级高于后台内容，但不改变后台页面整体布局。

## 代码范围

- 主要修改 `src/app/admin/page.tsx` 中的 `EvangelistSection`。
- 抽屉保持在同一文件内，避免为单一用途引入额外抽象或依赖。
- 继续使用现有 `/api/evangelist` 的 `POST`、`PUT` 和查询逻辑，不修改数据库结构。

## 验收标准

1. 从页面任意滚动位置点击“+贡献”，表单立即出现在当前视口内，并显示正确成员。
2. 点击已有贡献的“编辑”，抽屉载入正确的原始字段值。
3. 新增和编辑保存后，抽屉关闭，贡献列表和积分刷新。
4. 取消、关闭按钮、遮罩和 `Escape` 均能关闭抽屉且不提交数据。
5. 桌面端和移动端字段、按钮不溢出或重叠，键盘焦点可以进入抽屉。
6. 现有“其他”贡献类型及备注输入保持可用。

## 验证

- 增加针对抽屉关键文案和可访问性属性的组件源级测试。
- 运行现有测试、lint 和生产构建。
- 使用浏览器分别验证桌面和移动视口下的新增、编辑、取消和保存流程。
